## 측정 조건

- Testcontainers 전용 PostgreSQL 16.15. 실행마다 새 DB·동일 fixture 생성. 기존 DB에 연결하지 않는다.
- Java Corretto 25.0.4.1+10-LTS, JVM `-Xms512m -Xmx512m -XX:+UseG1GC -XX:ActiveProcessorCount=4`, 테스트 fork 1, JaCoCo 비활성화.
- Hikari: 기존 `BaseTestConfiguration` 설정(maximumPoolSize=5, 나머지 기본값). 동일 설정을 양 단계에 적용.
- `dev`, `disable-jobs`, `integration-test` 프로필. 고정 시계, 다운로드 stub, 외부 결제·메일·확장 호출 없는 읽기 전용 예약 상세 경로. Stripe mock은 기존 테스트 초기화 시 로컬 컨테이너로 실행되며 측정 요청은 결제를 호출하지 않는다.
- SQL/시간은 별도 Gradle 테스트 JVM으로 실행. SQL 모드만 DataSource에 JDBC 프록시를 설치한다. 시간 모드는 JDBC 프록시 자체가 없다.
- 실제 Jetty 임의 포트 → Java HttpClient HTTP/1.1 loopback 순차 GET. 합성 익명 예약에 접근 허용된 익명 요청이며 로그인 없음. 데이터 준비는 모두 측정 전 완료.
- 조건별 워밍업 10회. SQL은 이후 1회 요청의 execute* 호출 수 집계(바인딩 값 미수집). 전체 HTTP 요청 시작부터 본문 수신 완료까지, 그 외 fixture·백그라운드 SQL 제외.
- 시간은 워밍업 후 100회. `System.nanoTime()`을 `client.send` 직전과 `BodyHandlers.ofString()` 완료 직후에 읽는다. JSON 파싱·assert·데이터 준비는 구간 밖. 성공 요청만 정렬하여 중앙값, p95는 `ceil(0.95*N)`번째 값. 실패 수 별도 기록.
- SQL 분류: `configuration_ticket_category`를 포함하는 설정 상속 UNION 쿼리, 활성 카테고리 단건 조회(`ticket_category_with_currency where id = ... tc_status`), 미지정 재고 카테고리 count(`bounded = false`). 각 SQL 실행은 UNION 분기 수와 관계없이 1회.
- 전체 응답은 고정 합성 예약/티켓 UUID fixture의 JSON을 baseline snapshot과 구조적으로 비교하며 정책 예상값도 별도로 assert한다.
- 원본 로그·SQL 바인딩 값·비밀값은 커밋하지 않는다. 측정 산출물은 build 아래에서 집계한 표만 이 문서에 기록한다. snapshot은 합성 응답만 포함한다.

## 변경과 검증

- SQL 계측·시간 측정 모두 실제 HTTP 200과 티켓 수, 카테고리별 취소·메일·다운로드 예상값을 검사한다.
- SQL 모드에서 5개 조건의 전체 응답 JSON, 정책 9개 사례의 전체 응답을 합성 snapshot으로 저장한다. 최적화 후 동일 JSON과 구조적으로 비교한다.
- 정책 사례: 무료/유료 티켓, ACQUIRED/CHECKED_IN/TO_BE_PAID, 제한/비제한 카테고리, 미지정 재고 없음/있음, 조직→행사→카테고리 설정 상속과 카테고리 취소 override, 무료/유료 supplement, 행사 만료.
- 단일 티켓 로더 경로에서 무료/유료 supplement 취소 판단을 확인한다. 소유자 없는 익명 예약 허용, 소유자 설정 후 익명·알 수 없는 사용자 거부, 소유자 허용을 확인한다.
- 관련 테스트는 baseline SQL 1건(다중 조건·정책 assert 포함), baseline time 1건(측정 500회 + 워밍업 50회)이다. 측정표는 최종 실행 결과로 아래에 기록한다.

## 실패·리뷰·재개

- Git/Docker 접근은 기본 샌드박스에서 차단되어 승인된 도구 권한 확장으로 수행했다.
- 예비 SQL/시간 실행은 각 1건 통과했지만 기존 테스트 시계의 초·나노초가 변해 전체 응답 비교가 불안정한 점을 발견했다. 예약 만료 시각 고정 후 최종 코드로 양 모드를 다시 측정한다. 예비 시간값은 최종 표에서 제외한다.
- 정책 fixture 보강 중 유료 티켓의 VAT 상태 누락으로 기존 DB CHECK 제약에 걸린 실행 1건과 ZonedDateTime을 JDBC에 직접 전달한 실행 1건이 실패했다. fixture에 VAT 상태와 Timestamp 변환을 추가해 해결했다. 측정 요청 실패와 fixture 실패를 구분한다.
- 최종 측정 이후 제품 코드를 변경하고 동일 코드·fixture·명령으로 재측정한다. 시간 목표치나 결과에 따른 선택 재실행은 없다.
