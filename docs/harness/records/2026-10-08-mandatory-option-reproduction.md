## 재현 절차·확인 결과

1. 행사·Public 카테고리 가격을 100 CHF, 세금 0%로 설정한다.
2. Additional options에서 티켓마다 자동 적용되는 필수 고정 수수료 10 CHF를 생성한다.
3. Actions → create reservation에서 Public 티켓 2장과 합성 참석자 2명을 입력하고 Save and continue로 예약을 생성한다.
4. 관리자 예약 상세의 Order summary를 확인한다.
5. 예약의 URL to share를 열고 Contact Details의 Continue로 결제 전 Order summary를 확인한다. 약관 동의·Confirm·결제·메일 발송은 수행하지 않는다.
6. 같은 행사 공개 페이지에서 일반 예약으로 티켓 2장을 선택하고 합성 연락처를 입력해 결제 전 Order summary까지 진행한다.

| 경로·조건 | 실제 표시 | 기대·판단 |
|---|---|---|
| 관리자 예약 상세, 100 CHF × 2장 | 티켓 행만 존재, 합계 200 CHF | 필수 수수료 10 CHF × 2장 누락 |
| 관리자 예약 결제 전 화면 | 티켓 200 CHF, VAT 0, 합계 200 CHF | 기대 합계 220 CHF와 불일치 |
| 일반 예약 결제 전 화면 | 티켓 200 CHF + Required booking fee 20 CHF, 합계 220 CHF | 동일 설정에서 필수 수수료 정상 반영 |

- 검증 대상 제품 코드는 수정하지 않았다. 동일 행사·카테고리·옵션·티켓 수·세금 조건으로 관리자/일반 예약을 비교했으므로 필수 옵션 설정만의 문제로 단정하지 않고 관리자 생성 경로의 누락으로 확인한다.
- 최초 재현은 고정 수수료 2장 조건이었다. 사용자 요청으로 아래 추가 재현에서 고정·티켓 금액 비율 수수료의 1장·2장 조건을 확인했다. 접근 권한·다른 주문 동작은 이번 화면 재현 범위에 포함하지 않는다.

## 실패·조치·리뷰

- 기존 임시 Gradle 스크립트가 제거돼 최초 서버 실행 종료 코드 1. 동일 검증 DB용 스크립트를 새로 준비해 실행 성공.
- Docker가 중지돼 소켓 연결 실패. Docker Desktop과 기존 검증 컨테이너를 시작해 정상 연결.
- 옵션 제목 자동 입력의 변경 이벤트가 반영되지 않아 최초 저장이 거부됐다. 대화상자를 다시 열어 실제 키 입력·Tab으로 변경을 반영한 뒤 저장 성공. 수수료 누락의 재현 실패와 구분한다.
- 공개 페이지 수량 선택에서 option 값 2가 아닌 표시명 2로 선택해야 했다. 표시명 선택으로 일반 예약 2장 생성 성공.
- 자체 리뷰: 실제 옵션 설정·관리자 예약 상세·결제 화면·일반 예약의 같은 조건을 대조했다. 제품 코드·DB 스키마·실행 자격 증명·원본 로그를 저장소에 추가하지 않았다. 재현용 합성 데이터만 변경.


## 추가 재현 — 고정·비율 수수료의 단일·다중 티켓

- 요청: 고정 수수료와 비율 기반 수수료를 각각 1장·2장 조건에서 확인·캡처. 동일 main·제품 코드·실행 환경·행사·Public 카테고리 100 CHF·세금 0%를 유지했다. 기존 최초 재현 MD 외 작업 트리 변경 없음.
- 절차: 먼저 고정 정책에서 관리자/일반 예약 1장씩 생성했다. 이후 합성 행사의 기존 Required booking fee 옵션만 Mandatory percentage fee for tickets·10%로 변경하고, 관리자/일반 예약을 각각 1장·2장으로 생성했다. 관리자 상세와 결제 전 요약, 일반 예약 결제 전 요약을 대조했다. 약관 동의·Confirm·결제·외부 메일은 수행하지 않는다.
- 비율 정책은 티켓 금액 합계의 10%다. 옵션 제목은 Required booking fee로 유지되며 설정 화면의 실제 정책·10%·설명으로 조건을 확인했다. 주문 전체 금액(선택 옵션 포함)에 적용하는 별도 비율 정책은 이번 확인 범위에 포함하지 않는다.

| 필수 수수료 정책 | 티켓 수 | 관리자 예약 상세·결제 전 합계 | 일반 예약 수수료·합계 | 결과 |
|---|---:|---:|---|---|
| 고정 10 CHF / 티켓 | 1 | 100 CHF | 10 CHF·110 CHF | 관리자 수수료 누락 |
| 고정 10 CHF / 티켓 | 2 | 200 CHF | 20 CHF·220 CHF | 관리자 수수료 누락, 최초 재현 근거 |
| 티켓 금액 합계의 10% | 1 | 100 CHF | 10 CHF·110 CHF | 관리자 수수료 누락 |
| 티켓 금액 합계의 10% | 2 | 200 CHF | 20 CHF·220 CHF | 관리자 수수료 누락 |

- 비율 정책의 일반 예약은 수수료 행 1개에 총 수수료 10/20 CHF를 표시한다. 고정 정책처럼 수수료 수량이 티켓 수라고 주장하지 않는다.
- 실제 브라우저 조건 4개와 각 관리자/일반 경로를 확인했으며 자동 테스트 4건 통과로 계산하지 않는다. 세 조건은 이번에 새로 확인했고 고정 2장 조건은 앞선 동일 코드·환경의 실제 캡처를 재사용한다.

- 자체 대조: 실제 저장된 정책·유효 기간과 각 주문의 티켓 수·수수료 행 유무·합계를 확인했다. 입력 후 화면의 옵션 제목 갱신이 되지 않은 것을 확인해 실제 저장된 정책을 다시 읽었고, 정책은 10%로 반영되어 있어 그 조건으로 진행했다.
- 제품 코드·테스트·DB 스키마 변경·커밋·푸시·이슈 생성·노션 수정 없음. 요약 MD만 보완했다. 원본 로그·결과 JSON은 저장소에 추가하지 않는다.
