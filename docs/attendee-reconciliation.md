# 행사 명단 비교와 안내 초안

## 비교 기준

선택한 행사의 티켓을 기존 참석자 내보내기와 같은 `ACQUIRED`, `CHECKED_IN`, `TO_BE_PAID` 상태로 조회한다. 이는 티켓 상태이며 예약의 `COMPLETE` 여부를 추가 조건으로 사용하지 않는다. `TO_BE_PAID`도 포함되므로 결제 완료 명단으로 해석하지 않는다.

CSV `ID`는 기존 참석자 내보내기의 티켓 UUID이며 `E-Mail`은 티켓 참석자 이메일이다. 예약자 이메일을 비교하거나 이메일로 동일인을 추측하지 않는다. 같은 예약의 여러 티켓은 UUID별로 비교한다. 대상에 없는 UUID를 다른 행사에서 찾거나 취소·오류 예약으로 단정하지 않는다.

## CSV 형식

- UTF-8, BOM 허용, 쉼표 구분, 따옴표와 따옴표 내 줄바꿈 허용.
- 헤더 `ID`, `E-Mail` 필수, 순서 자유. 추가 열은 비교에 사용하지 않는다. 헤더 양끝 공백 제거, 빈 헤더·중복 헤더 거부.
- UUID는 양끝 공백을 제거하고 표준 36자 UUID를 검증·정규화한다.
- 이메일은 양끝 공백을 제거해 비교한다. 대소문자 차이는 불일치로 표시하며 두 값이 모두 비면 이메일 미등록을 별도로 표시한다.
- CSV 레코드 번호는 헤더를 1로 센다. 따옴표 내 줄바꿈은 하나의 레코드에 포함되며 텍스트 편집기의 물리 줄 번호와 다를 수 있다.
- 빈 파일·헤더만 있는 파일·필수 열 누락·형식 오류·열 개수 불일치·잘못된 UUID는 입력 오류로 처리한다. 해당 행을 제외해 누락 판정을 만들지 않고 CSV 수정을 안내한다.
- 요청은 CSV 본문으로 전송하며 원본 업로드 파일을 서버 디스크에 저장하지 않는다. 최대 5MiB·데이터 20,000레코드·필드 4,096자·100열. 시스템 결과와 전체 보관량도 제한한다.

## 결과와 초안

정상 일치, CSV에만 있음, 시스템에만 있음, CSV 중복, 이메일 불일치를 구분한다. 중복과 불일치가 같은 티켓에 함께 나타날 수 있다. 각 항목은 모든 CSV 레코드와 시스템 근거를 연결한다. 비교 시각 이후 시스템 변경은 재비교해야 한다.

AI 기능은 판정을 변경하지 않고 설명·안내 초안을 생성한다. AI 공급자와 보관 정책은 사용자 선택 후 확정한다. 이메일 발송·예약 수정·취소·환불은 수행하지 않는다. 원본 명단·개인정보·API 키를 로그나 저장소에 남기지 않는다.

## 확정한 보관·접근 정책

사용자 선택에 따라 비교 결과를 DB에 24시간 보관한다. 원본 CSV·파일명·무시한 열은 저장하지 않는다. UUID·참석자 이메일·시스템 상태·예약 ID·CSV 레코드 번호를 포함한 비교 근거를 AES-256-GCM으로 암호화한다. 무작위 nonce를 사용하며 비교 ID·행사 ID·생성 사용자를 인증 데이터로 묶는다. 집계 건수와 생성·만료 시각은 이력 조회를 위해 평문으로 보관한다.

조회·초안 생성·삭제마다 기존 행사 소유권 검사를 다시 적용한다. 행사 접근 권한이 있어도 다른 사용자가 만든 결과는 조회하지 못한다. 권한 회수 후에는 기존 비교 ID로 접근할 수 없다. 이력은 행사·사용자별 최대 10개다. 전체 유효 암호문은 100MiB, 개별 결과의 암호화 전 JSON은 10MiB까지 허용한다. 시스템 조회는 최대 20,001개에서 중단하고 비교 대상이 20,000개를 초과하면 오류를 안내한다.

만료 시점부터 재조회가 차단된다. 정리 작업은 1분 간격으로 만료된 결과와 오래된 호출 한도를 삭제한다. `disable-jobs` 프로필에서는 정리 작업이 실행되지 않으며 새 비교 저장 시 만료 결과도 정리한다. 정리가 중단된 동안에도 만료된 결과의 접근은 차단된다. 백업에 포함된 암호문은 DB 백업의 보관 정책에 따른다.

## 서버 설정

| Spring 설정 | 환경 변수 | 용도 |
|---|---|---|
| `alfio.attendee-assistant.encryption-key` | `ALFIO_ATTENDEEASSISTANT_ENCRYPTIONKEY` | Base64로 인코딩한 무작위 32바이트 AES 키. 비교 기능에 필수 |
| `alfio.attendee-assistant.ai-enabled` | `ALFIO_ATTENDEEASSISTANT_AIENABLED` | 기본 `false`. AI 초안 활성화 |
| `alfio.attendee-assistant.openai-api-key` | `ALFIO_ATTENDEEASSISTANT_OPENAIAPIKEY` | OpenAI API 키 |
| `alfio.attendee-assistant.model` | `ALFIO_ATTENDEEASSISTANT_MODEL` | 기본 `gpt-5.4-mini-2026-03-17` |
| `alfio.attendee-assistant.timeout-seconds` | `ALFIO_ATTENDEEASSISTANT_TIMEOUTSECONDS` | 1~30초, 기본 30초 |

암호화 키와 API 키는 비밀 관리 설정 또는 로컬 환경 변수로 주입한다. 저장소·채팅·명령 인자·로그에 넣지 않는다. 모든 앱 인스턴스에 같은 암호화 키를 제공해야 재조회할 수 있다. 키를 분실하거나 교체하면 기존 결과를 읽지 못하므로 결과를 만료·삭제한 뒤 키를 바꾸거나 별도 재암호화 절차가 필요하다. 키가 없거나 잘못되면 비교 저장을 중단하고 설정 안내를 표시한다.

AI는 기본 비활성화되며 비교와 재조회는 독립적으로 사용할 수 있다. 신규 Flyway 마이그레이션 `V206_2.0.0.61`은 비교 결과·호출 한도 테이블과 인덱스만 추가한다. 기존 예약·티켓·결제 테이블을 변경하지 않는다. 기능이 비활성화되어 있어도 앱의 기존 마이그레이션 절차에 따라 테이블이 생성된다.

테스트용 `alfio.attendee-assistant.test-endpoint`는 `dev` 프로필에서만 `http://127.0.0.1:<port>/...` 주소를 허용한다. 운영 연결은 기본 `https://api.openai.com/v1/responses`를 사용한다. 합성 키와 모의 서버는 테스트에서만 사용한다.

## AI가 만드는 초안

사용자 선택에 따라 자유 생성 대신 검증된 표현 조합을 사용한다. AI에 제공하는 것은 해당 비교 안에서만 유효한 참조 번호와 코드로 판정한 문제 유형이다. UUID·이메일·예약 ID·CSV 원문·행사명은 전송하지 않는다. AI가 유형의 설명 순서와 정중함·설명 길이를 선택하며, 서버는 허용된 문구를 조합한다. 응답에 없는 참조·추가 유형·누락 유형·중복 유형·임의 문장이 포함되면 초안 생성을 거부한다.

각 초안은 선택한 확인 항목에만 연결된다. 비교 판정·건수·근거는 AI 응답과 분리된 고정 영역이다. 운영자가 수정한 초안은 브라우저에만 존재하며 새로고침·결과 전환 시 사라진다. 서버에는 초안을 저장하지 않는다. 문구 다양성과 창작 자유도는 제한되며, 예약 변경이나 발송 도구를 AI에 제공하지 않는다.

한 번에 1~20개의 확인 항목을 선택할 수 있다. 같은 비교의 동시 호출을 차단하며 시간당 사용자 10회·전체 100회까지 허용한다. 실패한 호출도 한도에 포함된다. DB에서 한도를 예약하므로 서버 재시작과 다중 인스턴스에서도 유지된다. 시간대는 DB의 매 정시 단위이므로 경계에서 연속 호출이 가능하다. 호출은 자동 재시도하지 않는다. 출력은 최대 4,096토큰, HTTP 응답은 64KiB로 제한한다. 요청에는 `store: false`를 사용하지만 이 설정만으로 공급자의 모든 보관 정책이 사라지는 것은 아니다.

입력·캐시 입력·출력 토큰과 응답 시간을 화면에 표시한다. 선택 모델의 [공식 가격](https://developers.openai.com/api/docs/models/gpt-5.4-mini)은 2026-10-14 확인 기준 입력/캐시 입력/출력 100만 토큰당 $0.75/$0.075/$4.50이다. 지역 처리·가격 변경·모델 변경이 있을 수 있으므로 실제 비용은 공급자의 청구 내역을 확인한다. [구조화된 출력](https://developers.openai.com/api/docs/guides/structured-outputs)과 [Responses 저장 설정](https://developers.openai.com/api/docs/guides/migrate-to-responses)을 따른다.

## API

모든 경로의 기준은 `/admin/api/events/{eventName}/attendee-reconciliations`이며 세션 인증·기존 CSRF 헤더를 사용한다. 응답에는 `Cache-Control: no-store`를 적용한다.

| 메서드·경로 | 요청 | 응답 |
|---|---|---|
| `POST /` | `text/csv;charset=UTF-8` 원본 파일 내용, 최대 5MiB | 비교 ID·비교 시각·만료 시각·집계·AI 사용 가능 여부 |
| `GET /` | 없음 | 본인이 생성한 유효 비교 이력(최대 10개) |
| `GET /{id}` | `page` 기본 0, `pageSize` 기본 50/최대 100, `filter` 기본 `ATTENTION` | 집계와 해당 페이지의 근거 |
| `POST /{id}/drafts` | `{"references":["F-1"]}` JSON, 최대 8KiB | 참조별 설명·확인 방법·초안, 모델·사용량·시간 |
| `DELETE /{id}` | 없음 | 204, 생성 사용자·행사에 해당하는 결과 삭제 |

필터는 `ALL`, `ATTENTION`, `MATCHED`, `CSV_ONLY`, `SYSTEM_ONLY`, `DUPLICATE`, `EMAIL_MISMATCH`를 지원한다. 문제 유형별 건수는 티켓 기준이며 한 티켓에 여러 유형이 붙을 수 있다. 빈 이메일 일치는 `emailMissing`으로 별도 표시한다.

입력 오류는 400, 파일·결과 제한은 413, 행사 권한 거부는 403, 유효한 본인 결과 없음은 404다. 저장·호출 한도는 429, 동일 결과의 AI 호출 진행 중은 409, 설정·암호화 오류는 503, AI 실패·잘못된 응답은 502, 시간 초과는 504다. 안전한 오류 코드를 반환하고 원본 셀이나 공급자 오류 본문은 포함하지 않는다. AI 실패 시 비교 데이터는 삭제하거나 수정하지 않는다.
