# 명단 비교 비서 평가

## 동일 평가 입력과 판정 기준

실제 개인정보 대신 고정 합성 입력을 사용한다. `AttendeeReconciliationE2ETest`의 CSV와 DB fixture는 다음을 포함한다.

| 티켓 | CSV 레코드 | 시스템 | 정답 |
|---|---|---|---|
| UUID 끝 `001` | 2, `a@example.invalid` | ACQUIRED, 같은 이메일 | 정상 일치 |
| UUID 끝 `002` | 3: `b@example.invalid`, 4: `different@example.invalid` | CHECKED_IN, `b@example.invalid` | 중복 + 이메일 불일치 |
| UUID 끝 `003` | 없음 | TO_BE_PAID, `c@example.invalid` | 시스템에만 있음 |
| UUID 끝 `004` | 5, `unknown@example.invalid` | 비교 대상에 없음 | CSV에만 있음 |

시스템의 세 티켓은 같은 예약에 속한다. 정답은 정상 1티켓·확인 필요 3티켓이며 유형별 각각 1티켓이다. 중복과 불일치를 합쳐 하나의 문제로 기록하거나 확인되지 않은 취소·결제 사유를 추가하면 오답이다. 근거 레코드와 시스템 정보를 정확하게 연결해야 정답으로 센다.

## 수동 처리와 비서 사용 비교 절차

1. 동일 CSV·시스템 명단·정답표를 준비하고 도구 사용 순서와 연습 여부를 기록한다.
2. 수동 처리에서는 명단 대조·판정·근거 표시·안내 문구 작성·수정까지 시간을 잰다.
3. 비서 사용에서는 파일 선택부터 결과 검토·초안 생성·근거 확인·문구 수정·복사까지 시간을 잰다. AI 대기와 수정 시간을 제외하지 않는다.
4. 티켓별 모든 문제 유형·연결 근거를 정답표와 대조한다. 초안의 허위 사실은 별도 건수로 기록한다.
5. 수정 횟수는 사용자가 판정 또는 문구를 수정해 확정한 횟수로 정의한다. 키 입력 수와 혼동하지 않는다.
6. 실제 모델·시각·입력/캐시 입력/출력 토큰·가격·청구액을 기록한다. 모의 서버의 합성 토큰 값을 실제 사용량으로 사용하지 않는다.

| 항목 | 수동 처리 | 실제 비서 사용 |
|---|---|---|
| 수정 포함 전체 처리시간 | 미측정 | 미측정 |
| 티켓별 정확도 | 미측정 | 실제 모델 평가 미실행 |
| 판정/문구 수정 횟수 | 미측정 | 미측정 |
| AI 토큰·청구 비용 | 해당 없음 | 실제 API 미호출 |

## 이번 구현 검증의 범위

사용자가 API 키 부재에 따라 모의 서버 검증 후 커밋을 선택했다. 실제 앱·DB·브라우저 검증과 모델 품질 평가는 구분한다. 모의 서버 검증은 요청 형식·개인정보 제외·응답 근거 검증·오류·시간 초과·수정·복사 경로를 확인하며 한국어 모델 품질이나 사람의 시간 절감을 증명하지 않는다. 실제 OpenAI API 호출 비용은 이번 검증에서 0이고 합성 토큰은 청구되지 않는다.

자동 검증의 실제 실행 건수·결과와 시간은 [작업 기록](harness/records/2026-10-14-issue25-attendee-assistant.md)에 기록한다. 사람의 수동 비교 수치는 자동 테스트나 에이전트 시간을 사람 시간으로 환산해 채우지 않는다. 이슈 #25의 실제 모델·수동 대비 평가 조건은 후속 실측 전까지 미완료다.
