## 동일 평가 입력과 판정 기준

실제 개인정보 대신 고정 합성 입력을 사용한다. `AttendeeReconciliationE2ETest`의 CSV와 DB fixture는 다음을 포함한다.

| 티켓 | CSV 레코드 | 시스템 | 정답 |
|---|---|---|---|
| UUID 끝 `001` | 2, `a@example.invalid` | ACQUIRED, 같은 이메일 | 정상 일치 |
| UUID 끝 `002` | 3: `b@example.invalid`, 4: `different@example.invalid` | CHECKED_IN, `b@example.invalid` | 중복 + 이메일 불일치 |
| UUID 끝 `003` | 없음 | TO_BE_PAID, `c@example.invalid` | 시스템에만 있음 |
| UUID 끝 `004` | 5, `unknown@example.invalid` | 비교 대상에 없음 | CSV에만 있음 |

시스템의 세 티켓은 같은 예약에 속한다. 정답은 정상 1티켓·확인 필요 3티켓이며 유형별 각각 1티켓이다. 중복과 불일치를 합쳐 하나의 문제로 기록하거나 확인되지 않은 취소·결제 사유를 추가하면 오답이다. 근거 레코드와 시스템 정보를 정확하게 연결해야 정답으로 센다.

2026-10-14 [측정 결과와 채점 정정 근거](harness/records/2026-10-14-issue25-manual-agent-evaluation.md#측정-결과)를 옮겼다. 정확도는 이 합성 입력의 티켓 4개에 한정하며 모델 자체의 일반적인 정확도가 아니다. 비교 판정은 코드가 수행하고 AI는 검증된 표현의 순서·정중함·길이를 선택한다.

수동 원본은 헤더를 제외한 행 번호다. 헤더 1행을 더하면 비서의 CSV 레코드 번호와 같은 행을 가리키므로, 초기 채점의 표기 차이를 정정한 최종 판정·근거 정확도는 4/4, 100%다. 사후 채점 기준 정정은 작업 중 수정 총 2회에 합산하지 않았다. 원본은 기존 기록이 가리키는 Git 제외 경로 `ai/local-state/issue25-manual-evaluation/results-before-agent-measurement.md`에 보존한다.

### 시간의 포함 범위와 해석 한계

- 수동 처리: 사용자가 두 파일을 열기 직전부터 대조·판정·근거·안내문 작성·검토·수정·복사를 마칠 때까지. 안내문 예시·채팅 설명을 참고했고 질문 시간은 471초에서 제외했다. 그 외 오류·중단 여부와 시작/종료 시각은 원본에 미기록이다.
- 비서 사용: Codex가 CSV 선택 직전부터 비교·전체 4티켓 근거 검토·3개 선택·실제 AI 생성·문구 검토·복사 버튼 3개 실행 후 마지막 성공 안내 확인까지. 선택자 재탐색·클립보드 확인·원인 점검·도구 실행·모델 판단·대기·중간 설명을 포함한다. 로그인·서버 시작·준비는 제외했다. 판정·문구 수정은 필요 없어 하지 않았다.
- 에이전트는 fixture와 정답을 미리 알고 있었다. 작업자·시간 포함 범위·사전 지식이 다르므로 **471초와 204.15초로 사람의 생산성 향상률이나 시간 절감률을 계산하거나 해석하지 않는다.** 제한된 합성 사례의 참고 측정이다.
- 해당 에이전트 측정에서는 클립보드 읽기가 빈 문자열을 반환해 실제 내용 일치가 미검증이다. 별도 실제 모델 연결 E2E의 편집·클립보드 일치 통과 결과로 이 측정의 누락을 덮어쓰지 않는다.

동일한 사람이 두 방식을 사용하는 평가·다회 반복·순서 교차·일반적인 효과 검증은 미실행이다. 이번 이슈 #37의 완료 조건은 기존 기록 정리이며 신규 비교 평가가 아니다.

## 평가 절차와 이번 정리의 검증 범위

[수동 평가 절차](attendee-assistant-manual-evaluation.md)는 향후 별도 평가를 수행할 때의 입력·시작/종료·수정 횟수·채점·비용 확인 기준이다. 그 절차의 이상적인 조건을 기존 측정이 모두 충족했다고 간주하지 않는다. 사람 전체 처리시간을 자동 테스트·AI 응답 시간으로 환산하지 않고 미측정·미확인 값은 그대로 남긴다.

2026-10-16 문서·main 코드 대조와 합성 데이터·모의 AI를 사용한 화면 재검증 결과는 [이슈 #37 작업 기록](harness/records/2026-10-16-issue37-attendee-assistant-docs.md)에 구분해 기록한다. 신규 화면 재검증은 모델 품질·사람 생산성·실제 청구액의 추가 측정이 아니다. 초기 기록의 당시 미완료 표시는 보존하며, 후속 실측과 이번 문서 정리의 완료 여부를 구분한다.
