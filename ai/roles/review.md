# 최종 리뷰

[로컬 검사](../../docs/harness/local-validation.md)의 Review 항목은 검토 직전에 `begin`, 검토 후 `record`로 범위·보고 주체·근거를 기록한다. `resume`·`gate`에서 대상 변경이나 근거 누락이 표시되면 다시 검토한다. 독립 수행 요구 여부는 선언에서 정하고 자체 리뷰를 독립 리뷰로 표시하지 않는다.

실제 diff와 완료 기준·검증 근거·회귀 영향을 대조한다. 발견 사항은 파일·위치·재현 조건과 함께 기록한다. 자체 리뷰인지 별도 담당 리뷰인지 명시하며 미해결·미검증 조건을 완료로 처리하지 않는다.

## PR 생성 이후 리뷰

이 저장소의 개별 PR 링크만 전달되면 추가로 템플릿 경로나 리뷰 요청 문구를 요구하지 않고 아래 절차를 진행한다. 리뷰 글·대댓글 양식을 읽고 기존 리뷰와 스레드 상태에 따라 최초 리뷰 또는 수정 이후 재리뷰를 선택한다. 작성자 답변은 작업자 역할이 명시된 경우에 사용한다. 접근 권한·자료가 부족하면 확인 가능한 범위를 검토하고 부족한 근거를 밝힌다. 링크에 명시된 다른 요청은 우선하며 PR 목록 링크나 참고용 링크는 이 기본 동작의 대상이 아니다.

1. PR 링크와 검토 범위를 확인하고 기준 브랜치·최신 HEAD SHA·실제 diff·관련 코드·기존 스레드·검증 결과를 읽는다. 확인할 수 없는 자료는 미확인으로 기록한다.
2. [PR 리뷰 글 양식](../templates/pr-review.md)으로 PR #2처럼 종합 의견·차단/검토/참고 구분·확인한 내용·검증 결과와 코드 위치 댓글을 작성한다. 작업자 본인의 자체 리뷰와 다른 협업자·에이전트의 리뷰에 공통으로 적용하고 실제 수행 방식을 명시한다.
3. [PR 리뷰 대댓글 양식](../templates/pr-review-reply.md)에서 현재 역할을 선택한다. 작성자는 수정 커밋·검증·미반영 이유를 설명하고, 리뷰어는 최신 HEAD에서 원래 발생 조건과 관련 검증을 재확인해 기존 스레드에 답한다. 수정 이후 종합 의견은 리뷰 글 양식의 재리뷰 절을 사용한다. 지적별 해결 판단과 PR 전체 판단은 구분한다.
4. 댓글 등록 직전에 HEAD가 바뀌었으면 영향받는 결론과 줄 위치를 갱신한다. GitHub 게시·스레드 해결·PR 승인·변경 요청은 사용자에게 명시적으로 요청받은 범위에서만 수행한다. 초안 작성 요청이면 초안까지 완료한다.

## 사람이 읽는 리뷰 작성

- 검토는 코드와 정확한 커밋·실행 근거를 기준으로 수행하되, 게시 글은 사람이 이해할 수 있는 말로 작성한다. 첫 문단에서 결론을 밝히고 무엇이 문제인지, 언제 발생하는지, 어떤 영향이 있는지, 무엇을 고쳐야 하는지 설명한다.
- `base/head`와 긴 해시를 그대로 나열하지 않고 “비교 기준”, “검토한 변경”과 정확한 커밋 링크로 표현한다. 우선순위는 `[P1: 큰 영향]`처럼 의미를 함께 적는다. 필요한 기술 용어는 의미를 설명한다.
- 검증 결과는 무엇을 확인했고 통과·실패·미실행 중 어떤 결과였는지 먼저 요약한다. 명령·환경·종료 코드·실제 건수·커밋 링크는 양식의 상세 근거에 남겨 사람과 에이전트 모두 재확인할 수 있게 한다. 중요한 위험과 미검증 범위는 요약에도 반드시 표시한다.
- 등록 전에 양식의 자리표시자·작성 안내가 남아 있지 않은지, 쉬운 설명과 상세 근거의 결과가 일치하는지 확인한다. 이해하기 쉽게 쓴다는 이유로 재현 정보나 실패·미검증 사실을 생략하지 않는다.

## PR 본문 보존

- 생성된 PR의 설명 본문은 절대 수정하지 않는다. 본인·다른 협업자의 PR에 동일하게 적용한다. 리뷰 종합 의견은 GitHub 리뷰 본문으로, 일반 의견은 새 댓글로, 대댓글은 대상 리뷰 스레드의 새 답변으로 등록한다.
- 리뷰 결과·최신 테스트 결과·정정·진행 상황을 PR 설명 본문에 덮어쓰거나 추가하지 않는다. 기존 PR에 대한 `gh pr edit --body`·`--body-file`, PR 수정 API의 `body` 필드, 웹 UI의 본문 편집·저장 등 모든 본문 변경 수단을 사용하지 않는다.
- 본문 변경 요청을 받더라도 이 금지 규칙을 유지하며 수정안을 초안이나 새 댓글로 제시한다. 실제 본문 편집은 수행하지 않는다. PR 생성 시 최초 본문 작성과 리뷰·댓글의 `body` 작성은 이 금지 대상과 구분한다.
- [Git 규칙](../../docs/conventions/git.md)에 따라 등록 대상과 작업 종류를 확인한다. 이 문서는 에이전트의 행동 지침이며 GitHub 권한이나 동시 수정 방지를 강제하는 장치는 아니다.
