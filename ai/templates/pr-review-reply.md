# PR 리뷰 대댓글 양식

작업자 본인과 다른 협업자·그 협업자가 사용하는 에이전트가 기존 리뷰 스레드에 답할 때 사용한다. 작성자의 수정 보고와 리뷰어의 재확인을 아래 역할별로 구분한다. [PR #2의 대댓글](https://github.com/WookJaes/alf.io/pull/2#discussion_r4183892737)처럼 작성자는 수정 커밋·변경·검증·한계를 설명한다. [리뷰 역할](../roles/review.md)에 따라 최신 HEAD·기존 지적·작성자 답변·관련 diff와 검증 근거를 확인하고 아래 상황에 맞는 양식 하나를 선택한다.

## 작성 기준

- 답변은 기존 지적에 대한 현재 판단부터 쓰고, 근거와 필요한 다음 행동을 간결하게 잇는다. 상대의 의도·역량을 추측하지 않는다.
- 해당 스레드와 재확인한 HEAD를 식별할 수 있게 커밋 또는 코드 링크를 연결한다. 없는 링크·테스트 결과를 만들어 넣지 않는다.
- 리뷰어는 “수정했다”는 답변만으로 해결을 선언하지 않는다. 원래 발생 조건이 해소됐는지 확인하고, 코드 확인과 실제 실행 결과를 구분한다.
- 기존 코드 댓글과 같은 문제에는 기존 스레드로 답한다. 새로 발견한 별개 결함은 [리뷰 글 양식](pr-review.md)의 코드 위치 댓글로 작성한다.
- 수정이 확인되면 해결 근거를 쓰고, 남은 조건이 있으면 구체적으로 적는다. 기존 지적이 잘못됐거나 요구사항상 문제가 아니면 지적을 철회하고 판단이 바뀐 근거를 밝힌다.
- 생성된 PR의 설명 본문은 절대 수정하지 않는다. 다른 사람의 댓글도 편집하지 않고 기존 스레드에 새 답변으로 남긴다. 본문 정정이 필요해도 초안이나 새 댓글로 제시한다.
- 자리표시자를 실제 내용으로 바꾸고, 해당 없는 항목은 생략한다. 템플릿은 댓글 등록·스레드 해결·PR 승인을 자동으로 실행하지 않는다.

## 작성자: 수정·검증 보고

```markdown
<커밋 SHA 또는 링크>에서 <원래 지적을 해결하기 위한 변경>을 반영했습니다. <추가한 회귀 테스트와 원래 발생 조건을 확인한 방법>을 보완했습니다.

<실행 환경>에서 `<명령>`으로 <종료 코드·실제 테스트 건수·결과>를 확인했습니다. <실행하지 않은 환경·검증과 남은 영향>은 아직 확인하지 못했습니다.
```

## 작성자: 미반영·후속 처리 답변

```markdown
<지적 또는 제안>은 <근거와 이유>에 따라 <현재 동작 유지 / 후속 처리 제안>으로 답변드립니다. <이번 PR에서 처리할 범위와 남은 영향>을 설명드립니다.

<요구사항·코드·검증 근거 또는 이미 존재하는 후속 이슈 링크>. <차단·검토 항목이 남으면 해결된 것으로 표시하지 않고 필요한 확인 사항 명시>
```

후속 이슈가 없으면 링크를 만들지 않는다. 작성자의 후속 처리 제안을 합의된 결정으로 표현하지 않으며, 리뷰어의 확인 전까지 해당 항목은 미해결로 남긴다.

## 리뷰어: 수정 확인

```markdown
<커밋 또는 코드 링크>에서 기존 지적의 <발생 조건>이 해소된 것을 확인했습니다. <수정으로 동작이 어떻게 바뀌었는지와 근거>에 따라 이 지적은 해결됐다고 판단합니다.

검증: <직접 실행한 명령·실제 건수·결과 또는 확인한 CI·코드 근거. 코드만 확인했다면 실행 검증은 미실시라고 명시>
남은 확인: <관련 미검증 범위 또는 없음>
```

## 리뷰어: 추가 수정 필요

```markdown
<재확인한 커밋 또는 코드 링크>에서도 <남은 발생 조건>에서 <문제와 영향>이 남아 있습니다.

근거: <재현 절차·관련 코드·실제 실패 결과>
필요한 조치: <해결해야 할 최소 조건과 재확인 방법>
```

## 리뷰어: 정보 부족으로 판단 보류

```markdown
<확인한 커밋 또는 근거>에서는 <확인된 내용>까지 확인했습니다. 다만 <빠진 조건·결과>가 없어 기존 지적의 해결 여부는 아직 판단하기 어렵습니다.

<구체적인 질문 또는 필요한 증거>를 확인할 수 있을까요? <해당 정보가 원래 지적의 판단에 필요한 이유> 때문입니다.
```

## 리뷰어: 기존 지적 철회

```markdown
<코드·요구사항·검증 링크>를 다시 확인한 결과, <판단이 바뀐 이유>에 따라 기존 지적을 철회합니다. <현재 동작이 요구사항을 충족하는 근거 또는 처음 검토에서 놓친 사실>을 확인했습니다.
```
