# PR 리뷰 글 양식

[PR #2](https://github.com/WookJaes/alf.io/pull/2)의 리뷰 형식을 기준으로 한다. 작업자의 자체 리뷰와 다른 협업자·그 협업자가 사용하는 에이전트의 리뷰에 공통으로 적용한다. 실제 수행 방식은 밝히고 자체 리뷰를 독립 리뷰로 표시하지 않는다. 사용 절차는 [리뷰 역할](../roles/review.md)을 따른다.

이 문서의 “리뷰 본문”은 GitHub 리뷰에 붙이는 종합 의견이다. PR 작성자가 작성한 변경 설명 본문과 별개이며, 생성된 PR의 설명 본문은 절대 수정하지 않는다. 수정이 필요해도 초안이나 새 댓글로 제시한다.

## 작성 기준

- PR 본문·연결 이슈의 완료 조건·기준 브랜치·최신 HEAD의 실제 diff·관련 코드·기존 스레드·검증 결과를 확인한다. 확인하지 못한 자료는 미확인으로 적는다.
- 첫 문단에 검토 범위와 결론을 적고, 차단·검토·참고 기준, 확인한 내용, 검증 결과 순서로 작성한다. 사람과 에이전트가 같은 결론을 이해할 수 있도록 문제·발생 상황·사용자 영향·필요한 조치를 쉬운 말로 연결한다. PR #2의 정보 구조를 따르되 기술 표현을 그대로 복제하지 않는다.
- 게시 문장에 `base/head`, `SHA`, `diff`, `CI`, `종료 코드`만으로 설명하지 않는다. “base”는 “비교 기준”, “head”는 “검토한 변경”, “SHA”는 “커밋 식별자”, “diff”는 “변경 내용”, “CI”는 “자동 검사”, “종료 코드”는 “명령 실행 결과”로 풀어 쓴다. 필요한 기술 용어는 처음 사용할 때 의미를 설명한다.
- 결론과 검증 요약은 펼쳐진 본문에 둔다. 정확한 명령·실행 환경·종료 코드·건수는 아래 “상세 검증 근거”에 남겨 에이전트와 개발자가 재확인할 수 있게 한다. 긴 커밋 해시를 문장에 나열하지 않고 정확한 커밋을 가리키는 링크에 변경 내용 또는 짧은 식별자를 표시한다. 링크를 확인할 수 없으면 짧은 식별자를 쓰고 링크 미확인을 밝힌다.
- **차단**: 병합 전에 해결이 필요한, 근거가 확인된 문제. **검토**: 실제 사용에 영향을 주어 수정 방향이나 처리를 확인할 문제. **참고**: 병합을 막지 않는 후속 개선 제안. 검토 항목도 영향에 따라 해결이 필요할 수 있으므로 병합 전 해결 필요 여부를 명시한다.
- 우선순위는 결함의 영향에 따라 P0(즉시 대응할 치명적 문제), P1(큰 영향), P2(일반적인 결함), P3(낮은 영향)로 표시한다. 게시 제목에는 `[P1: 큰 영향]`처럼 번호와 의미를 함께 적고 실제 영향은 본문에서 설명한다. 병합 판단을 나타내는 차단·검토·참고와 구분한다. 참고 제안에는 P번호를 강제하지 않는다.
- 종합 의견에는 각 항목을 짧게 요약하고, 재현 조건과 수정 방향은 해당 파일의 인라인 댓글에 적는다. 인라인 댓글을 사용할 수 없으면 파일·줄과 상세 근거를 종합 의견에 포함한다. 같은 문제를 기존 스레드에 중복 등록하지 않는다.
- 직접 실행한 검증과 기존 CI·작업 기록에서 읽은 결과를 구분한다. 환경·명령·종료 코드·실제 건수와 기준 커밋을 남긴다. 미실행·실패·스킵·테스트 0건을 통과로 적지 않는다.
- 지적이 없으면 확인한 범위에서 문제를 발견하지 못했다고 적고 빈 항목을 생략한다. 근거 부족은 확인 질문으로 표시한다. 참고 제안이나 취향에 따른 변경을 병합 차단 조건으로 만들지 않는다.
- 승인·변경 요청은 검토 결론과 실제 GitHub 리뷰 상태를 구분한다. 자체 작성 PR은 GitHub에서 승인할 수 없으므로 자체 리뷰는 COMMENT로 남긴다. 외부 등록은 요청받은 범위에서 수행한다.
- 아래 자리표시자를 실제 내용으로 대체하고 해당 없는 절·안내는 생략한다.

## 최초 리뷰 종합 의견

```markdown
<변경 범위>를 <연결 이슈 또는 요청의 완료 조건>과 함께 검토했습니다. <확인된 문제에 따른 수정 필요 / 검토 범위에서 추가 문제를 발견하지 못함 / 판단 보류와 그 이유>를 말씀드립니다.

댓글은 다음 기준으로 구분했습니다.

- **차단**: 병합 전에 해결이 필요한, 근거가 확인된 문제입니다.
- **검토**: 실제 사용에 영향을 주어 수정 방향이나 처리를 확인할 문제입니다.
- **참고**: 병합을 막지 않는 후속 개선 제안입니다.

### 확인한 내용

1. **[차단] <문제 요약>.** <발생 조건·영향·필요한 수정과 검증을 간략히 작성>
2. **[검토] <문제 요약>.** <근거·확인할 수정 방향·병합 전 해결 필요 여부>
3. **[참고] <후속 제안>.** <제안 이유와 이번 PR의 차단 조건이 아님을 명시>

<인라인 댓글을 실제 작성한 경우에만: 각 항목의 구체적인 재현 조건과 수정 방향은 해당 파일의 인라인 댓글에 남겼습니다.>

### 검증 결과

<자체 리뷰 / 작업에 참여하지 않은 협업자의 리뷰 등 실제 수행 방식>로 <검토 범위>를 확인했습니다.

- 직접 확인: <무엇을 확인했고 어떤 결과였는지. 예: 문서 링크 검사와 회귀 테스트 14개가 모두 통과했습니다. 실패·건너뛴 테스트는 없습니다.>
- 자동 검사·기존 기록 확인: <직접 실행과 구분한 결과와 확인한 실행 링크 또는 미확인>.
- 확인하지 못한 범위: <생략한 검사·이유·판단에 남는 영향 또는 없음>.
- 검토한 변경: <정확한 커밋을 가리키는 링크; 표시 문구는 변경 요약 또는 짧은 식별자>.

<details>
<summary>상세 검증 근거</summary>

- 비교 기준: <대상 브랜치 이름과 정확한 기준 커밋 링크>.
- 검토한 변경: <정확한 검토 커밋 링크>.
- 실행 환경: <OS·필요한 도구 버전·명령을 실행한 위치>.
- 직접 실행한 명령: `<명령>` — <종료 코드(0은 정상 종료)·실제 테스트 건수·성공/실패/건너뜀 결과>.
- 변경 내용·공백 검사: `<명령>` — <실제 결과 또는 미실행 이유>.
- 확인한 자동 검사·기존 기록: <검토한 커밋에 해당하는 실행 링크와 결과 또는 미확인>.

</details>

<상세 근거는 요약과 같은 결론을 뒷받침해야 함. 미검증 범위와 중요한 위험은 접힌 부분에만 적지 않음. 문서 검사 통과를 제품 기능 검증으로 표현하지 않음>
```

## 코드 위치 댓글

최신 diff의 파일·줄에 하나의 문제씩 등록한다. PR #2처럼 제목에 분류와 결함 우선순위를 함께 쓰고, 재현·영향·수정 방향·재검증 순으로 설명한다.

```markdown
**[<차단 / 검토>][<P번호: 영향의 쉬운 설명>] <문제와 필요한 수정의 짧은 제목>.**

<사용자가 어떤 상황에서 어떤 동작을 하면> <어떤 문제가 발생하는지> 확인했습니다. <관련 코드가 이 문제를 일으키는 이유를 쉬운 말로 설명>합니다.

이 상태에서는 <사용자나 시스템에 생기는 영향>이 있습니다. <문제를 해결할 최소 수정 방향>으로 보완해 주시면 좋겠습니다.

수정 후에는 <원래 문제가 발생한 상황에서 기대하는 동작>을 확인 부탁드립니다. <검토 항목이면 병합 전 해결 필요 여부와 이유>

재확인 근거: <파일·줄의 코드 링크, 재현 절차 또는 실행한 명령·실제 결과. 기술 정보는 앞의 설명을 뒷받침하도록 작성>
```

참고 댓글은 `**[참고] <후속 제안 제목>.**`으로 시작한다. 현재 한계·제안 이유·후속 방향을 설명하고 이번 PR의 병합 차단 조건이 아님을 명시한다.

## 수정 이후 재리뷰 종합 의견

PR #2의 재리뷰처럼 기존 항목의 해결 여부를 먼저 정리한다. 특정 스레드의 답변은 [대댓글 양식](pr-review-reply.md)을 사용한다.

```markdown
수정 사항을 재확인했습니다. <기존 차단·검토 항목의 해결 여부와 추가 문제 유무에 따른 결론>. <실제로 승인·변경 요청을 제출하는 경우에만 해당 상태를 명시>

- **차단 항목 <해결 / 미해결>**: <수정 내용·원래 발생 조건의 재검증 근거>.
- **검토 항목 <해결 / 미해결>**: <수정 내용·확인 결과·남은 조건>.
- **참고 항목**: <작성자가 합의한 후속 처리 또는 현재 상태>. <이번 PR 승인 조건 포함 여부>.

검토한 변경: <수정 내용 또는 짧은 식별자로 표시한 정확한 커밋 링크>.

검증 결과: <어떤 동작을 다시 확인했고 어떤 결과였는지, 직접 실행한 테스트 건수와 자동 검사 확인을 구분>.
확인하지 못한 범위: <미실행 검증·이유·남은 영향 또는 없음>.

<details>
<summary>상세 검증 근거</summary>

<최초 리뷰와 같은 방식으로 정확한 비교 기준·검토 커밋 링크, 실행 환경·명령·종료 코드·실제 건수·자동 검사 링크를 기록>

</details>
```
