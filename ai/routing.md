# 역할 라우팅

기본은 현재 Codex의 순차 수행이다. 필요한 역할 지침만 읽는다. 사용자에게 분담 요청을 받으면 사용 가능한 하위 에이전트 도구로 파일 소유권을 나눈다. 도구가 없으면 순차 수행이라고 기록한다.

| 요청·상황 | 경로·다음 행동 |
|---|---|
| 조사·설명 | 관련 조사 → 답변 |
| 이 저장소의 개별 PR 링크만 입력 | [리뷰](roles/review.md)와 연결된 양식 읽기 → 최신 HEAD 검토 → PR #2 형식 초안; 기존 게시 승인이 있으면 승인 범위에서 등록 |
| 브랜치·커밋·PR 작업 | [Git 규칙](../docs/conventions/git.md) 확인 → 사용자 요청 범위에서 수행 |
| 기능 구현·수정 | 문서 명세 → 오케스트레이션 계획 → 구현 → 실행 검증 → 리뷰 → 문서 정리 |
| 테스트·화면 확인 | 실행 검증 → 필요 시 진단 → 결과 보고 |
| 문서·하네스 수정 | 문서 수정 → 구조·내용 검증 → 리뷰 → 보고 |
| 실패·리뷰 지적 | 실패 기록 → 진단 → 해당 구현·문서·환경 수정 → 재검증·리뷰 |
| 테스트 0건·필수 확인 누락 | 완료 금지 → 검증 보완 또는 제약 보고 |
| 검증 후 코드·설정 변경 | 영향받는 검증·리뷰 재수행 |
| 요청 밖 기존 문제 | 진단 역할로 이슈 초안; 현재 작업 영향 명시 |
| 관련 실패 지식 필요·해결 확인 | 기억 조회·정리; 충돌하는 기억은 제외 |
| 사용자 변경·권한·필수 정보 부족 | 요청 우선 적용, 필요한 질문과 이유 기록, 가능한 작업 진행 |

## 책임 문서

- [문서](WORKFLOW.md#공통-작업-책임): 명세와 안내.
- [구현](WORKFLOW.md#공통-작업-책임): 코드와 회귀 테스트.
- [진단](roles/diagnosis.md): 원인과 이슈 초안.
- [리뷰](roles/review.md): diff와 근거 대조.
- [진행 관리](WORKFLOW.md#공통-작업-책임): 범위·다음 행동·완료 판단.
- [실행 검증](roles/verification.md): 실제 테스트·화면·DB 확인.
- [기억](roles/memory.md): 실패 이력과 검증된 지식.

순차 역할 전환을 독립 에이전트 실행이라고 표시하지 않는다. 별도 담당이 있는 경우 구현 파일 작성자를 하나로 유지하고 같은 파일 수정은 직렬화한다.
